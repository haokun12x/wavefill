Wavefill

让超长上下文的每一波计算，都填满芯片。

Wavefill 基于开源推理引擎 NInfer，包含一组内核优化和一份完整的性能分析。方法是：先实测硬件上限，再建立只有一两个参数的性能模型；用模型找出损失、预测收益，最后在整机上验证。目标是让 agent 超长上下文的 prefill 用满 170 个 SM 中的每一个。

The Film · 影片

从带宽上限，到芯片里的波次

影片 5 分 47 秒，讲清这个项目的来龙去脉：先看清芯片，再测出两种上限；然后说明 decode 为什么已经到顶、prefill 的损失在哪里，以及两项优化如何把损失拿回来。所有数字都是本机实测。

I
The Ceiling · 上限

先测清天花板

不知道上限，就无法判断一个内核“好不好”。所有效率都以本机实测的上限为分母，不用规格书的名义值。

1.70TB/s
DRAM 纯读上限

TMA bulk 拷贝和 ld.global.nc.v4 是两条完全不同的数据通路，结果都停在 1702–1705 GB/s，即名义值的 95%。按 Little 定律，全卡要约 1 MiB 的在途读请求才能喂饱 DRAM（有负载时延迟约 450 ns）。

251 / 501TFLOP/s
mma.sync · FP32 / FP16 累加

同一个张量核心，FP16 累加的吞吐恰好是 FP32 累加的两倍。这个 2× 是后文第二项优化的出发点。

600W
功耗墙

长时间 prefill 会持续顶在功耗墙上。内核越忙，DVFS 给出的频率越低：SM 频率中位数从 2745 MHz 降到 2595 MHz。

Roofline

一边贴着斜线，一边远离屋顶

可达性能 P = min(π, β·I)。decode 每读一个字节只做 2–3.6 次运算，比拐点低 40–70 倍，被钉在带宽斜线上。prefill 注意力的算术强度是 6144 FLOP/B，远在拐点右侧，属于计算受限，但原内核只用到峰值的 60%。

两段要用完全不同的思路对待：decode 只能移动上限，prefill 则要找回损失。

decode · 已经到顶

13.1 ms 里只差 1.71 ms

生成一个 token 要跑 641 个内核、读 19.35 GB，带宽下界是 11.4 ms（88 tok/s），实测 12.9–13.1 ms，GPU 忙碌率 98.6%。剩下的差距里没有能大块挖回的部分。

最大的短板是 NVFP4 下投影 GEMV。它在真实 decode 里只跑到带宽的 83%，单独跑却有 97%，区别只在于它前面跑的是哪个内核。根因是冷取指：全展开后的代码有 6520 条指令（102 KiB），每条指令只执行一次，每层调用时都要从 L2 重新取。把循环收成 4 路后，代码缩到 20 KiB，内核从 35.14 µs 降到 32.58 µs，整机 decode +1.25%，输出逐位不变。

再往上，预取、PDL 和小内核融合加起来，现实上只有 +4–8%。要大幅提速，只能减少每 token 读取的字节数，或者每读一遍权重产出更多 token：MTP3 投机解码已经做到 2×。

II
The Chip · 芯片

用簇驻留能力，反推 GPC 拓扑

线程块簇的 S 个 CTA 必须同时落在同一个 GPC 里。实测不同簇大小时全卡最多能同时驻留多少个簇，就能推出芯片的布局：8 个 16-SM GPC 加 3 个 14-SM GPC。完整的 GB202 是 12 个 GPC、192 个 SM，这块卡屏蔽了一个完整 GPC 和 3 个 TPC。

推理过程

S = 9…14 时驻留簇数恒为 11，说明有 11 个 GPC，而且每个至少有 14 个 SM。S = 15、16 时是 8，说明其中 8 个有 16 个 SM。170 − 8×16 = 42 = 3×14。

S = 1…8 的实测值 170、85、52、41、30、22、22、19，全部与上式吻合。由此还能得到两条结论：

S = 2 是唯一不浪费 SM 的簇大小，因为所有 GPC 的 SM 数都是偶数。S = 7 严格优于 S = 6，两者驻留的簇数一样多，但 S = 7 用了 154 个 SM。

III
The Waves · 波次

60% = 75.3% × 80%

head dim 是 256，原内核的 Q/K/V 占了 96 KB 共享内存（上限 99 KB），寄存器用到 254/255，所以一个 SM 只能放一个 CTA。一个 tile 独占一个 SM，170 个 SM 一波一波地跑。只要 tile 数不是 170 的整数倍，最后一波就会有 SM 空转。

原内核：每个 tile 一个 CTAWavefill：S 个 CTA 组成一个簇，平分同一个 tile 的 key空转的 SM

横轴是 170 个 SM，纵轴是时间，面积就是工作量。上下文 64k，24 个查询头，每个 tile 是 64 行查询 × 一个头。右侧的 TFLOP/s 是实测值，包含两项优化的共同效果。

一个参数解释六个形状

实测吞吐 ÷ 波次效率 = 常数

η(T) = U / (170·⌈U/170⌉),   U = ⌈T/64⌉ × 24

上下文远大于 T 时，各 tile 的工作量几乎相同，所以内核吞吐应该等于 η(T) 乘以一个与 T 无关的单 SM 效率 R。六个形状的实测值都落在 R = 200 TFLOP/s 上，误差在 ±0.7% 以内；改后同样是一个常数，R = 230。

于是原内核的 60% 可以精确拆成两个相乘的因子：75.3% 的波次效率，乘以 80% 的单 SM 效率（200/251）。两个因子分别用一项优化处理。

IV
Two Cuts · 两项优化

填满波次，抬高屋顶

第一项用线程块簇把空转的 SM 填满，第二项把一半运算换到双倍吞吐的累加路径上。两项都不需要额外显存，也都以可证明的数学性质为前提。

① cluster split-KV

在线 softmax 是一个幺半群

把一段 key 上的部分结果记为三元组 s = (m, ℓ, o)，两段可以合并：

s₁ ⊕ s₂ = ( M,  ℓ₁em₁−M + ℓ₂em₂−M,  o₁em₁−M + o₂em₂−M )

⊕ 满足结合律和交换律，单位元是 (−∞, 0, 0)。所以 key 范围可以任意切分、以任意顺序合并，在精确算术下结果都相同；实现里固定按 rank 顺序归约，保证同样的输入得到同样的输出。

同一个簇里的 S 个 CTA 通过分布式共享内存（DSMEM）直接读取彼此的部分和，3 次 cluster.sync() 就在片上完成合并。Flash-Decoding 式的做法要 50 MB 全局工作区外加第二个内核，这里都不需要。

主机端用代价模型选择 S，最大可选 8：

cost(S) = ⌈U / CS⌉ · ( ⌈B̄ / S⌉ + δ·[S>1] )

64k 上下文、1024 token 分块。8 种簇大小的预测与实测最大偏差是 3.3%，排序完全一致：S = 6 只用了 132 个 SM，甚至比不切分还慢。S = 2 时等效 2.5 波，波次填充率 90.4%。

② FP16 累加 P·V

可证明不溢出，也不掉进次正规区

QK 和 PV 各占一半运算。只把 PV 换成 FP16 累加，计算上限就从 251 提高到

πnew = 2 / (1/251 + 1/501) = 334 TFLOP/s

QK 不能换：logit 的绝对误差会直接变成概率的相对误差（∂P/P = ∂x）。PV 不一样，P ∈ [0, 1]，部分和有界。每个 64-key 块按本块自己的最大值取值：

P̂j = 2−6·exj − mt  ⇒  Σ P̂j ≤ 64·2−6 = 1  ⇒  ‖p‖∞ ≤ (1+ε)·max‖vj‖∞

部分和是 V 各行的次凸组合，所以溢出在数学上不可能发生，这个上界与上下文长度和注意力分布都无关。块结束时用一条 FMA 乘 β 折回 FP32 累加器。

如果用全局运行最大值，attention sink 会把普通 key 推到 x − m ≈ −10 以下：那里 FP16 只剩次正规数，相对精度约 4%，低于 e−13.2 直接变成 0。用块内最大值后，每块最大的一项恰好是 2−6，块与块之间的量级差交给 FP32 系数吸收。sink 场景下误差 1.629e-3，而 BF16 舍入本身的下限是 1.628e-3；原内核是 1.634e-3。

1.40× = 波次效率 0.753 → 0.899 （×1.19） × 单 SM 吞吐 200 → 232 （×1.16）

Results · 结果

每个结论都至少经过两层证据：微基准、算子基准（冷 L2、CUDA Graph）、引擎内 nsys 轨迹、整机新旧二进制交替 A/B。

场景改前 → 改后提速

功耗墙

整机为什么拿不到内核的全部收益

64k prefill 期间，整卡一直顶在 600 W 的功耗墙上（降频原因是 SW power cap）。新内核让张量核心更忙，开关活动因子 α 变大，同样的功耗只能换到更低的频率。

1.40 × 2595 / 2745 = 1.32与引擎内实测的注意力提速一致

没有改动的内核慢了 3.2%，小于 5.5% 的频率降幅，因为其中一部分受访存限制。每次 64k prefill 的能量从 6.76 kJ 降到 6.17 kJ（−9%）：在功耗墙下，真正该看的是每焦耳完成的工作。
